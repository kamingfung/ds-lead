# Solve a Problem Top-Down

Solve a problem by testing a stated hypothesis, not by intuition. A clear hypothesis gives the analysis a direction and states which evidence would change your mind. Each step asks whether the evidence supports or rejects a specific claim. MECE means mutually exclusive, collectively exhaustive: the parts do not overlap, and together they cover the whole question.

## Principles

- **Show a repeatable path.** Anyone who follows the same steps on the same data should reach the same answer, so a lucky guess never passes as a result. Write the steps down so a colleague can repeat them.
- **Build the tree for this problem.** A framework is only a starting template, so shape the branches around the hypothesis in front of you.
- **Define and isolate the cause first.** Name the cause and confirm it before you propose any fix.

## Step 1: Frame the Problem

1. Restate the problem in one or two sentences.
2. Express each change as a relative figure: a cost that goes from 40 to 50 rises 25%.
3. Confirm every objective, the time frame and a measurable success criterion.
4. Organize your notes into three separate parts: objectives, data and the issue tree.
5. Put early solution ideas on a parking list.
6. State one falsifiable first hypothesis, and label it an informed guess when you know little.
7. Build the issue tree, where each branch is a condition you can test.
   - Every branch tests the hypothesis.
   - The branches are MECE.
   - If all branches hold, the opposite hypothesis cannot.
8. Walk the stakeholder through the main branches before you compute anything.

## Step 2: Drill Down

- Aim for roughly 70% numbers and 30% qualitative evidence. Treat this split as a rule of thumb. Numbers show what happened and how much; interviews and context show why.
- Start with the branch that removes the most doubt. Close one branch at a time, and state in one sentence what it showed. Return to the top of the tree before you pick the next branch.
- Segment every total and average by product, customer group, channel or region. A flat total revenue can hide one product up 20% and another down 15%.
- Use the same definitions, units and time windows in every branch, so the numbers can be compared.
- Compare against the past, three to five years back, and against peers. If peers moved the same way over the same period, a market-wide shift is the likelier explanation.
- Write each formula in words before you add numbers, and check that every result is a plausible size. Example: revenue equals customers times orders per customer times average order value.
- After each branch, write a one- or two-sentence interim summary. Keep it short enough to read aloud in under 30 seconds. Revise the hypothesis when the evidence contradicts it. Hold each conclusion loosely: when new data cuts against it, say so and change course at once instead of defending it.
- Stop digging into a branch once more data would no longer change the recommendation.

## Step 3: Synthesize Top-Down

1. Lead with the recommendation. The first sentence should answer the question the stakeholder asked.
2. Back it with at most three quantified reasons, ordered by weight. Each reason should trace back to a branch in the issue tree, so the reader can follow the logic.
3. Restate the recommendation, then name the risks, the assumptions to watch and the next analyses.
4. For several options, keep an options-by-criteria scorecard from the start, and present it in the synthesis. Score each option on the same criteria and weights, so the ranking follows from the evidence.

## Anti-Patterns

1. **No hypothesis.** Analysis without a claim to test produces charts that prove nothing.
2. **Solution before cause.** A fix proposed before the cause is isolated targets the wrong problem.
3. **A framework that tests nothing.** Branches that no data can confirm or reject add structure without insight.
4. **Hopping between branches.** Switching before a branch closes leaves every question half answered.
5. **Ending with a list of activities.** A list of what the team did, instead of what it found, leaves the decision maker without an answer.
